# PRD 020 — Year Navigation for the Monthly Insight Page

**Triage: ready-for-agent** — no further triage needed.

## Problem Statement

The Monthly Insight page (`/insight/monthly`) is hardcoded to the **current calendar year**. The hook derives every date range from `new Date().getFullYear()`: the monthly totals fetch, the gap-filling (Jan → current month), the projection length (`remainingMonths`), and the rolling-average window.

As a result, the user can only ever see the current year's monthly breakdown. Transactions from previous years are invisible on this page — there is no way to navigate to them, compare them, or revisit them. The chart title ("This Year"), the month list ("This Month"), and the projection all silently assume the current year.

## Solution

Add a **list of years that have transactions** at the bottom of the Monthly Insight page (below the monthly list), in the same vertical-list style as the monthly list. Each row shows the year and its yearly net amount. Clicking a year switches the whole page to that year:

- The area chart and monthly list show that year's 12 months (Jan–Dec).
- The pie chart shows a month of that year (defaulting to the year's last month with transactions).
- The projection line is suppressed for completed years; the chart header instead shows that year's own average monthly net and its actual year-end balance.
- "This Year" / "This Month" labels only apply when viewing the current year.

The list is derived from the existing `GET /api/v1/reports/totals?period=year` endpoint — **no new API endpoint is needed**.

## User Stories

1. As a user of the Monthly Insight page, I want to see a list of all years that contain transactions, so that I know which years I can explore.
2. As a user of the Monthly Insight page, I want the year list to show only years with transactions, so that I never click into an empty year.
3. As a user of the Monthly Insight page, I want the page to open on the current year (as it does today), so that the default view is unchanged.
4. As a user whose current year has no transactions yet, I want the page to fall back to the most recent year that does, so that I never land on an empty view.
5. As a user of the Monthly Insight page, I want to click a year and see that year's monthly totals in the area chart and monthly list, so that I can review past years.
6. As a user who clicks a past year, I want the pie chart to show that year's most recent month with transactions, so that the top of the page shows meaningful data immediately.
7. As a user who switches years, I want my previous month selection to be reset, so that the pie never shows a month from a different year than the rest of the page.
8. As a user who switches back to the current year, I want the pie to return to "This Month", so that the default behavior matches today.
9. As a user viewing a past year, I want the monthly list to show all 12 months (Jan–Dec, zeros for inactive months), so that I see the complete year at a glance.
10. As a user viewing a past year, I want the "This Month" row/highlight to disappear, so that no month is misleadingly marked as current.
11. As a user viewing a past year, I want the chart to show only the historical accumulated curve (no dashed projection), so that I don't see a fake forecast for a completed year.
12. As a user viewing a past year, I want the chart header to show that year's average monthly net and its actual year-end balance, so that the header stays informative.
13. As a user viewing a past year, I want to click a month in the chart or monthly list and see that month's category pie chart, so that month-level drill-down still works for past years.
14. As a user viewing the current year, I want the projection and rolling-average behavior to be unchanged, so that existing functionality is preserved.
15. As a user, I want each year row to show the yearly net amount, so that the list doubles as a quick yearly summary.
16. As a user, I want the current year's row highlighted in the primary color, so that I can see where I am relative to "now".
17. As a user, I want the years ordered newest-first, so that the most relevant year is at the top of the list.
18. As a user with no transactions at all, I want a muted "no transactions yet" message in the year list section, so that the page explains its own emptiness.
19. As a user on a slow connection, I want the year list to show a loading skeleton, so that the page does not appear broken while data loads.
20. As a user on a slow connection, I want existing chart/list data to stay visible while a year switch is loading, so that the page does not flicker to skeletons.
21. As a developer, I want the year-aware month filling and statistics to live in pure, testable functions, so that the logic can be verified in isolation.
22. As a maintainer, I want the implementation to reuse the existing totals endpoint, so that no new API contract or mock handler is introduced.

## Implementation Decisions

### Data source — reuse the totals endpoint

The year list is derived from `GET /api/v1/reports/totals?period=year` with **no** `from`/`to` parameters (both are optional in the existing contract). It already exists in `API.md`, `reportsService.ts`, the MSW handler, and the offline (IndexedDB) service.

- The response rows (`TotalsReportRow[]`) are filtered down to their `period` field — a `"YYYY"` string per year with transactions, Main book only.
- The `net` field of each row is displayed on the year row.
- **No API.md, service, type, MSW, or offline-service changes are required.**

### Selection state

```typescript
// inside useMonthlyInsight:

selectedYear: string | null   // null = "most recent year with transactions"
activeYear: string            // resolved: selectedYear ?? mostRecentYearWithData ?? currentYear
```

`null` semantics elegantly cover the default: if the current year has transactions, the most recent year with transactions **is** the current year (today's default preserved); otherwise it is the newest year that does. Before the year list has loaded, `activeYear` falls back to the current year.

The hook exposes `years`, `selectedYear`, `selectYear`, plus loading/error state for the year-list fetch. The year list is fetched once on mount (`getTotals({ period: "year" })`), independent of the selected year.

### Pure helpers — `monthlyInsightUtils.ts` (new, in `pages/insight-monthly/`)

The year-aware calculations are extracted into pure functions with a simple, stable interface:

```typescript
fillYearMonths(rows: MonthlyReportRow[], year: string, isCurrentYear: boolean, currentMonth: number): MonthlyReportRow[]
// current year: fills Jan → currentMonth; past years: fills all 12 months (Jan–Dec).
// Missing months are zero-filled; periods outside `year` are discarded.

lastMonthWithTransactions(rows: MonthlyReportRow[], year: string): string | null
// The highest "YYYY-MM" period present in `rows` for the given year; null if none.

yearStats(rows: MonthlyReportRow[], year: string): { averageMonthlyNet: number; yearEndNet: number }
// averageMonthlyNet: sum of that year's monthly nets / count of months with transactions
//   (months without transactions excluded from the divisor — consistent with the
//   average endpoint semantics).
// yearEndNet: sum of that year's monthly nets (the accumulated curve's last point,
//   since the seed is zero).

resolveDefaultYear(years: string[], currentYear: string): string
// The most recent year with transactions, or currentYear if the list is empty/loading.
```

### `useMonthlyInsight` orchestration

- **Monthly totals fetch**: range becomes `activeYear-01-01` → `(activeYear+1)-01-01` (unified for all years, replacing the current-year-specific computation). Refetches when `activeYear` changes.
- **Gap-filling**: `fillYearMonths` (above) replaces the current hardcoded Jan → `currentMonth` loop.
- **Pie default month**: when `activeYear !== currentYear` and no month is selected, the pie month defaults to `lastMonthWithTransactions(rows, activeYear)`. When the user switches years, `selectedMonth` is **reset**: to that year's last month with transactions (past years) or to `null` (= "This Month", current year). Switching back to the current year resets to `null`.
- **Rolling-average fetch**: runs **only** when `activeYear === currentYear`. For past years it is skipped entirely.
- **Projection**: `accumulatedData` appends projected rows **only** when `activeYear === currentYear`. For past years the accumulated data ends at December (the seed remains `0` — "each year is of its own").
- **Chart header values**: the hook exposes the chart's average and end value plus a "is current year" flag. For the current year these remain the rolling-window average and projected end (unchanged). For past years the average is `yearStats(...).averageMonthlyNet` and the end value is `yearStats(...).yearEndNet`.
- **Dead code removal**: the unused opening-balance fetch (`getBookStats asOf previousYearEnd`) is deleted — its result is already unused (seed hardcoded to 0).

### `PeriodList` — optional list-label prop

`PeriodList` currently derives its header label from `labelForCurrent === "Today" ? "Daily Net" : "Monthly Net"`. A new optional `listLabel` prop is added; when provided it is used as the header label verbatim. Default behavior (daily/monthly) is unchanged, so `DailyList` and `MonthlyList` are unaffected.

### `YearList` (new, in `pages/insight-monthly/`)

A thin wrapper around `PeriodList`, mirroring `MonthlyList`:

- `periods` = years mapped to `{ period: year, amount: net }`, newest-first (PeriodList sorts descending automatically).
- `currentPeriod` = the real current year string; that row is primary-highlighted but labeled plainly (`"2026"`, not "This Year") — year numbers are self-identifying.
- `formatLabel` = identity.
- `labelForCurrent` = the current year string; clicking the current-year row calls `onSelect(null)` → returns to the default year (the standard `PeriodList` "current" semantics).
- `listLabel` = `"Yearly Net"`.
- When the fetched year list is empty (and not loading/error), renders a muted "No transactions yet" message instead of the list header.

### `MonthlyList` — year context

`MonthlyList` receives the active year (or an `isCurrentYear` flag). "This Month" label + primary highlight are applied only when the active year is the current year; otherwise no row is marked current (every month labeled Jan…Dec).

### `MonthlyAreaChart` / `PeriodAreaChart` — past-year header

- `MonthlyAreaChart`'s title becomes dynamic: `"This Year"` for the current year, otherwise the year number (e.g. `"2024"`) — mirroring the pie title convention.
- `PeriodAreaChart` gains an optional `endLabel` prop (default `"Projected End"`). For past years the hook passes the year's actual year-end balance with `endLabel = "Year End"`; the average box shows that year's own average monthly net.
- Projection suppression is data-driven: for past years the hook simply returns no projected rows, so no dashed line renders.

### Page wiring

`InsightMonthlyPage` renders the `YearList` section at the **bottom** of the page (below the monthly list) and threads the new props through the hook, chart, and lists. No other pages are touched.

## Testing Decisions

### What makes a good test

- Tests focus on **external behavior**: what the hook returns, what the page renders, what the user sees — not internal state or call ordering.
- Pure functions are tested by input/output pairs — no mocks.
- Hook tests use MSW-mocked API responses and assert on returned state and derived data.
- Edge cases: empty year list, current year absent from the list, sparse years (single month of data), year with no transactions in some months.

| `YearList` | `YearList.test.tsx` (new) | Component | Renders years + net amounts; current-year row highlighted; click year → `onSelect(year)`; click current year → `onSelect(null)`; empty message; loading skeleton; error. |
| `InsightMonthlyPage` | `InsightMonthlyPage.test.tsx` (updated) | Page | Year list renders at bottom; switching year updates chart/list data; "This Year"/"This Month" labels switch to explicit dates for past years. |

## Out of Scope

- **Backend changes** — no new endpoints; the totals endpoint is reused as-is. Backend implementation of that contract is separate work.
- **Daily Insight year navigation** — the daily page keeps its current-month scope.
- **URL state / deep-linking** — the selected year lives in component state only, consistent with the existing month selection. No `useSearchParams` is introduced.
- **Caching** — the year list is fetched on each mount; no new caching strategy.
- **Fixing the stale-pie-during-switch glitch** — when a year/month switch is in flight, the pie deliberately keeps showing the previous data until the new fetch resolves (accepted behavior; no data clearing is added).
- **Changing current-year behavior** — the current year's projection, rolling average, "This Month" list, and "This Year" title are unchanged.
- **Book-closing entries** — years/periods containing only closing entries behave exactly as the existing report endpoints already define.

## Further Notes

- **No `API.md` changes.** The totals endpoint is already documented (with optional `from`/`to`) and already has an MSW handler and an offline (IndexedDB) implementation — the mock will correctly return years for the generated transaction data (which currently spans two calendar years).
- Frontend-first development applies: MSW serves as the backend during development.
